## CONCEPT sm-basics | Linux Basics, Boot and Kernel
idea: A Linux system boots in stages: firmware, bootloader, kernel, then systemd. Knowing each stage tells you where to look when something breaks.
point: Boot order: UEFI or BIOS, then GRUB2, then the kernel and initramfs, then systemd (PID 1), then the default target.
point: modprobe loads a module with its dependencies. insmod does not. lsmod lists loaded modules. modinfo describes one.
point: /proc and /sys are virtual filesystems built in memory. Runtime kernel settings live under /proc/sys and are set with sysctl.
point: Copyleft licences such as the GPL require derived work to keep the same licence.
memory: FBKS: Firmware, Bootloader, Kernel, Systemd.
card: Linux boot order? => Firmware (UEFI/BIOS), GRUB2, kernel + initramfs, systemd (PID 1), default target.
card: modprobe vs insmod? => modprobe loads a module plus its dependencies. insmod loads one file and ignores dependencies.
card: List loaded kernel modules? => lsmod
card: Stop a module loading at boot? => Add a blacklist line in a file under /etc/modprobe.d/.
card: Make a sysctl setting survive reboot? => Put it in a file in /etc/sysctl.d/, then run sysctl --system.
card: Rebuild the initramfs on RHEL? On Debian? => RHEL: dracut -f. Debian/Ubuntu: update-initramfs -u.
card: Apply changes from /etc/default/grub on RHEL? => grub2-mkconfig -o /boot/grub2/grub.cfg
card: What are /proc and /sys? => Virtual filesystems built in memory by the kernel. Rebuilt every boot.
