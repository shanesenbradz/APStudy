## CONCEPT sm-basics | Linux Basics, Boot and Kernel
idea: A Linux system boots in stages: firmware, bootloader, kernel, then systemd. Knowing each stage tells you where to look when something breaks.
point: Boot order: UEFI or BIOS, then GRUB2, then the kernel and initramfs, then systemd (PID 1), then the default target.
point: modprobe loads a module with its dependencies. insmod does not. lsmod lists loaded modules. modinfo describes one.
point: /proc and /sys are virtual filesystems built in memory. Runtime kernel settings live under /proc/sys and are set with sysctl.
point: Copyleft licences such as the GPL require derived work to keep the same licence.
memory: FBKS: Firmware, Bootloader, Kernel, Systemd.
card: Linux boot order? => Firmware (UEFI/BIOS), GRUB2, kernel + initramfs, systemd (PID 1), default target.
card: modprobe vs insmod? => modprobe loads a module plus its dependencies. insmod loads one file and ignores dependencies.
card: List loaded kernel modules? => lsmod
card: Stop a module loading at boot? => Add a blacklist line in a file under /etc/modprobe.d/.
card: Make a sysctl setting survive reboot? => Put it in a file in /etc/sysctl.d/, then run sysctl --system.
card: Rebuild the initramfs on RHEL? On Debian? => RHEL: dracut -f. Debian/Ubuntu: update-initramfs -u.
card: Apply changes from /etc/default/grub on RHEL? => grub2-mkconfig -o /boot/grub2/grub.cfg
card: What are /proc and /sys? => Virtual filesystems built in memory by the kernel. Rebuilt every boot.

## CONCEPT sm-storage | Storage, LVM and Filesystems
idea: Disks are split into partitions or LVM volumes, formatted with a filesystem, then mounted. LVM lets you grow storage without downtime.
point: LVM order: pvcreate, vgcreate, lvcreate, mkfs, mount.
point: lvextend -r grows the LV and the filesystem together. XFS can grow but cannot shrink.
point: Mount by UUID in /etc/fstab and test with mount -a before rebooting.
point: Software RAID uses mdadm. Check its health in /proc/mdstat.
memory: P-V-L: Physical, Volume group, Logical. Build from the bottom up.
card: LVM build order? => pvcreate, vgcreate, lvcreate, then mkfs and mount.
card: Grow an LV and its filesystem in one step? => lvextend -r -L +5G /dev/vg/lv
card: Grow XFS? Grow ext4? => XFS: xfs_growfs /mountpoint. ext4: resize2fs /dev/vg/lv.
card: Can XFS shrink? => No. Back up, recreate smaller, restore.
card: Add a new disk to an existing VG? => vgextend vg0 /dev/sdd (after pvcreate).
card: /etc/fstab field order? => Device, mount point, type, options, dump, fsck pass.
card: Test /etc/fstab before reboot? => mount -a
card: Where is software RAID status? => /proc/mdstat (arrays built with mdadm).

## CONCEPT sm-files | Files, Text Tools and Backups
idea: Most admin work is moving, finding and archiving files. Learn tar, rsync, find and a few text tools well.
point: tar -c creates, -x extracts, -t lists. Add z for gzip, j for bzip2, J for xz.
point: rsync -av copies only changes. --delete makes the target an exact mirror.
point: find searches by name, time, size and permissions. xargs passes results to another command.
point: dd copies raw blocks. Check if= and of= twice before you press Enter.
memory: tar flags: Create, eXtract, lisT, and z-j-J for gz, bz2, xz.
card: tar flags to create, extract, list? => -c create, -x extract, -t list. Add -f for the file name.
card: tar compression flags? => -z gzip, -j bzip2, -J xz.
card: Extract a tar into a different folder? => tar -xvf file.tar -C /target
card: Make rsync mirror deletions too? => rsync -av --delete src/ dest/
card: In dd, which is input and which is output? => if= is input, of= is output. Swapping them overwrites the source.
card: find files changed in the last 7 days? => find /path -mtime -7
card: Why sort before uniq? => uniq only removes duplicates that sit next to each other.
card: Hard link vs symbolic link? => Hard link: same inode, same filesystem only. Symlink: stores a path, breaks if the target is deleted.

point: virsh list --all shows running and stopped VMs.
point: qcow2 images support thin provisioning and snapshots. raw images are simple and fast.
point: Bridged networking puts VMs on the real LAN. NAT hides them behind the host.
point: Live migration needs compatible CPUs and the same shared storage path on both hosts.
memory: virsh for the shell, virt-manager for the mouse.
card: Tool to manage KVM from the shell? GUI? => virsh. virt-manager.

card: Disk format with thin provisioning and snapshots? => qcow2
card: Network mode that puts VMs on the real LAN? => Bridged. NAT hides them behind the host.
